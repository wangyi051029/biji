# 设备工况智能预测系统 设计报告

**课程**：制造智能技术课程设计
**选题**：面向小样本工业工况预测：融合统计学习的深度学习智能计算优化方案
**日期**：2026-09-02

---

## 一、背景调研（研究意义）

### 1.1 问题背景
在工业设备运维场景中，传感器可采集大量设备运行过程中的时序数据，但普遍存在三类问题：
1. **有效标签样本少**：设备故障属于低频事件，带标签的故障样本稀缺，直接训练深度学习模型极易过拟合；
2. **数据噪声大**：传感器数据受环境干扰，含随机噪声与异常点；
3. **硬件算力受限**：工业现场多为普通 PC，缺乏高端 GPU，大模型难以落地部署。

### 1.2 研究意义
在有限算力与小样本条件下，实现设备工况（剩余寿命 RUL）的准确预测，对设备预测性维护、降低非计划停机成本具有重要工程价值。单纯深度学习易过拟合且算力开销大；单纯统计学习虽对小样本友好但深层时序特征挖掘能力不足。本系统验证"统计学习 + 深度学习 + 智能计算优化"融合方案，在尽量不损失精度的前提下降低计算开销、抑制过拟合，具有实际工程参考意义。

### 1.3 相关工作
- C-MAPSS 数据集（NASA）是 PHM/RUL 预测领域的经典公开基准（Saxena et al., PHM08）；
- 深度学习用于 RUL 预测的主流模型包括 LSTM、GRU、CNN 等；
- 模型轻量化技术包括剪枝、量化、知识蒸馏等（李威等，2022）；
- 小样本学习与统计学习方法（周志华《机器学习》）。

## 二、方案设计

### 2.1 总体思路
系统围绕三个技术方向形成完整闭环：

| 技术方向 | 定位 | 在系统中的实际作用 |
|---------|------|------------------|
| 统计学习 | 数据层 | 数据清洗、噪声识别、特征筛选、数据集划分、k 折交叉验证 |
| 深度学习 | 模型层 | 双层 LSTM 时序网络提取退化特征，回归预测 RUL |
| 智能计算优化 | 优化层 | 模型剪枝、参数量化、学习率调度，降低训练/推理算力开销 |

### 2.2 系统架构
采用 **B/S（Browser/Server）** 架构：
- **前端**：HTML + CSS + JavaScript + ECharts，六个功能页面；
- **后端**：FastAPI 提供 REST API；
- **数据库**：SQLite（datasets / models / predictions / experiments 四张表）；
- **算法模块**：统计学习、深度学习、智能计算优化三模块。

### 2.3 技术选型
| 组件 | 选型 | 理由 |
|------|------|------|
| 编程语言 | Python 3.8+ | 数据科学与 AI 生态成熟 |
| 深度学习框架 | PyTorch (CPU) | 支持自定义剪枝/量化，无需 GPU |
| 统计学习 | scikit-learn / scipy | 特征筛选、交叉验证、假设检验 |
| 后端 | FastAPI + Uvicorn | 轻量、异步、自动文档 |
| 数据库 | SQLite | 零配置，适合课程设计与 demo |
| 前端 | 原生 + ECharts | 无构建依赖，开箱即用 |

## 三、数据资源构建

### 3.1 数据集
选用 **NASA C-MAPSS 涡扇发动机退化仿真数据集**（公开工业时序数据，约 44MB）：
- 4 个子集 FD001~FD004，含 3 个运行设置 + 21 路传感器测量；
- 每台发动机从正常到故障的全生命周期时序数据，混有传感器噪声；
- 任务为剩余寿命（RUL）预测，契合"小样本工业工况预测"。

来源链接（已验证有效）：
- https://phm-datasets.s3.amazonaws.com/NASA/6.+Turbofan+Engine+Degradation+Simulation+Data+Set.zip
- https://data.phmsociety.org/nasa/

### 3.2 数据预处理（统计学习方法）
预处理流程见 `data/数据预处理说明.md`，核心步骤：
1. **清洗**：缺失值检测、常值传感器剔除；
2. **噪声识别**：IQR 准则 + Z-score 准则（仅标记不删除）；
3. **特征筛选**：低方差剔除 → 高相关冗余剔除 → 单因素 ANOVA 显著性检验；
4. **标签构造**：分段线性 RUL（上限 125）；
5. **划分**：按发动机单元划分 train/val/test（防泄漏）；
6. **交叉验证**：GroupKFold 5 折（同机不跨折）；
7. **标准化**：StandardScaler 仅在训练集拟合。

预处理结果（FD001）：21 个传感器筛选保留 14 个，噪声率 5.93%，无缺失值。

### 3.3 数据入库
预处理结果与模型、预测、实验记录统一写入 SQLite，支持后续查询与复现。

## 四、系统实现

### 4.1 后端服务（FastAPI）
`backend/main.py` 提供 REST API：健康检查、数据集列表、预处理、特征查询、模型训练、在线预测、智能优化、压缩对比、预测记录、实验记录等。

### 4.2 数据库（SQLite）
`backend/database.py` 实现四张表：
- `datasets`：数据集元信息（规模、特征数、噪声率）
- `models`：模型记录（类型、参数量、推理耗时、MAE/RMSE、剪枝/量化状态）
- `predictions`：预测记录（单元、真值、预测值、误差）
- `experiments`：实验记录（配置与指标 JSON）

### 4.3 算法模块

#### （1）统计学习模块 `backend/algorithms/statistical.py`
实现了数据清洗、噪声识别（IQR+Z-score）、特征筛选（方差+相关+ANOVA）、RUL 标签、数据集划分、GroupKFold 交叉验证、标准化流水线。

#### （2）深度学习模块 `backend/algorithms/deep_learning.py`
实现双层 LSTM 时序网络：
```
输入(窗口30×特征15) → LSTM(隐藏96) → LSTM → 全连接(32) → 输出RUL
```
- 训练：Adam + 权重衰减(L2 正则) + Huber Loss（对噪声鲁棒）；
- 正则化：Dropout + 早停 + 梯度裁剪；
- 学习率调度：ReduceLROnPlateau；
- 滑动窗口构造时序样本，按单元隔离。

#### （3）智能计算优化模块 `backend/algorithms/optimization.py`
- **模型剪枝**：按权重幅值将最小 30% 权重置零，稀疏化冗余连接；
- **参数量化**：权重 float32 → int8 线性量化模拟，保留剪枝零值；
- **对比评估**：参数量、模型大小、推理耗时、MAE/RMSE 前后对比。

### 4.4 前端界面（B/S）
`frontend/index.html` 提供六个页面：
1. **总览**：系统指标卡片 + 特征筛选/模型推理耗时图表；
2. **数据管理**：预处理按钮、已入库数据集表格、特征筛选详情；
3. **模型训练**：LSTM 训练参数配置与模型列表；
4. **智能优化**：剪枝比例/量化位数配置，雷达图压缩对比；
5. **在线预测**：选择子集/模型/单元号，输出 RUL 预测；
6. **对比分析**：基准 vs 优化模型指标对比。

## 五、测试与集成调试

### 5.1 自动化测试（pytest）
共 28 个测试用例，全部通过（`python3 -m pytest`）：
- 统计学习模块：数据加载、缺失/常值检测、RUL 标签、噪声识别、特征筛选、划分防泄漏、GroupKFold、预处理流水线（10 个）；
- 深度学习/优化模块：滑动窗口、LSTM 训练预测、模型保存/加载往返、剪枝、量化、对比（6 个）；
- 数据库层：四张表 CRUD（4 个）；
- API 集成：健康、数据集、预处理、特征、训练、预测、优化、对比、预测记录（8 个）。

### 5.2 实验验证（FD001 子集）
在普通 CPU 上完成训练与优化，实验结果：

| 指标 | 基准模型（LSTM） | 优化后（剪枝30%+int8量化） | 变化 |
|------|----------------|--------------------------|------|
| 参数量 | 121.03 K | 85.23 K | **-29.6%** |
| 模型大小 | ~484 KB | ~85 KB | **-82.4%** |
| MAE | 12.06 | 12.10 | 基本持平 |
| RMSE | 15.86 | — | 基本持平 |
| 推理耗时 | 0.06 ms | 0.05 ms | 微降 |

> 结论：剪枝+量化在几乎不损失精度（MAE 12.06→12.10）的前提下，实现模型参数减少约 30%、存储减少约 82%，验证了融合方案"降低算力开销、保持精度"的目标，适配普通 PC 部署。

- 使用 `backend/seed.py` 一键初始化，可复现全部流程；
- 已处理警告：zscore 常值列数值警告、FastAPI on_event 弃用警告。

### 6.2 关键 prompt 策略
1. **任务拆解**：将课程设计拆分为数据、模型、优化、服务、前端、测试、文档等子任务，逐项提示；
2. **约束说明**：在 prompt 中明确"使用 PyTorch CPU、无需 GPU、B/S 架构、三个技术方向、统计学习方法处理数据"等约束；
3. **验收标准**：要求"自动化测试全部通过、数据来源链接有效、普通 PC 可运行"；
4. **上下文工程**：先读取仓库中《方案设计》《选题说明》再开发，保证代码与方案一致；
5. **规格驱动**：先产出需求规格说明书再分步实现。

完整提示词记录见 `prompt/` 目录（JSON 格式，随阶段更新）。

### 6.3 AI 出错案例及纠正过程
| 案例 | 问题 | 纠正过程 |
|------|------|---------|
| 1 | 模型保存/加载时隐层维度不匹配（hidden=96 模型被默认 64 重建） | 在 meta 中持久化架构参数（input_size/hidden_size/num_layers），加载时按 meta 重建 |
| 2 | 剪枝后参数量减少率显示为 0 | 量化函数未保留剪枝的精确零值，改为 dequant 后 masked_fill 恢复零权重 |
| 3 | 数据预处理输出混入未筛选原始列 | 修正为仅输出筛选后标准化特征列 |
| 4 | 前端预测接口与后端参数不一致 | 统一为前端传"子集+模型+单元号"，后端自动加载数据预测 |
| 5 | FastAPI 新版 TestClient 不触发 startup 导致测试表缺失 | 改用 lifespan 事件 + 测试 fixture 显式建表 |

> 以上错误均由人工审查识别并修正，修正逻辑已充分理解，非黑盒使用 AI 输出。

## 七、总结与展望

### 7.1 成果总结
本课程设计完成了一套面向小样本工业工况预测的 B/S 应用系统：
- 完整实现"统计学习数据预处理 → LSTM 深度学习建模 → 剪枝/量化智能计算优化 → 在线预测 → 对比分析"业务闭环；
- 三个技术方向（统计学习/深度学习/智能计算优化）均有实质代码与实验支撑，非装饰性引入；
- 28 项自动化测试全部通过，普通 PC（CPU）可一键运行；
- 数据、参数、实验结果全程入库并纳入 git 版本管理，过程可复现。

### 7.2 不足与展望
- 当前以 FD001 子集为主实验，后续可扩展到多工况子集（FD002/FD004）并引入迁移学习；
- 预测精度仍有提升空间，可尝试注意力机制、Transformer 等更强时序模型；
- 量化目前为模拟量化，后续可实现真实 int8 推理（如 torch.quantization）；
- 可进一步集成实时数据接入、告警推送等工程化能力。
